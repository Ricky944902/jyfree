# 02 · 编译指南

**[简体中文](02-编译指南.md)** · **[English](02-build-guide.en.md)**

## 1. 依赖

| 依赖 | 用途 | 必需 |
|---|---|---|
| `gcc` ≥ 6 / `make` | 编译 | ✅ |
| `libx11-dev` | `jyfree-gui` 图形界面版 | 仅 GUI |
| `libpthread` `libdl` `librt` | ptrace / dlopen / shm_open | ✅ |
| aarch64 交叉工具链 | 在 x86 上编译 aarch64 版 | 交叉时 |

### 安装依赖

**UOS / Debian 系：**

```bash
sudo apt update
sudo apt install build-essential libx11-dev
```

**交叉编译工具链：**

```bash
sudo apt install gcc-aarch64-linux-gnu
```

**Fedora / RHEL：**

```bash
sudo dnf install gcc make libX11-devel
sudo dnf install gcc-aarch64-linux-gnu
```

## 2. 一键编译

```bash
./scripts/build.sh            # 本机编译 + 依赖检查 + 架构检查
./scripts/build.sh --check    # 只检查环境，不编译
./scripts/build.sh --debug    # 调试版 (-O0 -g3 -DDEBUG)
./scripts/build.sh --install  # 编译并安装到 ~/.local
./scripts/build.sh --clean    # 清理
./scripts/build.sh --cross    # 交叉编译 aarch64
./scripts/build.sh --help     # 帮助
```

---

## 3. 用 Makefile 直接编译

```bash
make              # 全部: jyfree + jyfree-gui + libjyfree.so
make cli          # 仅命令行版
make gui          # 仅图形界面版
make payload      # 仅 payload
make debug        # 调试版
make clean        # 删中间文件 (obj/)
make distclean    # 连 bin/ 一并删
make arch-check   # 检查架构
make install      # 安装
make help         # 全部目标说明
```

产物：

```
bin/jyfree          命令行版
bin/jyfree-gui      图形界面版
bin/libjyfree.so    payload（必须与 jyfree 同目录）
```

中间文件在 `obj/`。

---

## 4. 交叉编译（x86 上构建 aarch64 版）

**方式一：脚本**

```bash
./scripts/build.sh --cross
./scripts/build.sh --cross aarch64-none-linux-gnu-
```

**方式二：Makefile**

```bash
make ARCH=aarch64 CROSS=aarch64-linux-gnu-
```

产物传到目标机：

```bash
scp bin/* user@target:/usr/local/bin/
```

---

## 5. 架构要求（重要）

> **payload 中的内联钩子地址是 aarch64 专用。**

`Student` 是 **ET_EXEC 非 PIE**，所以 `nm` 给出的地址就是运行地址，例如：

```
ShowLockScreen  @ 0x441ed4
StartMonitorPassive @ 0x44e670
```

jyfree 直接把这些地址写进 payload 的补丁里。因此：

| 编译架构 | 结果 |
|---|---|
| aarch64 | ✅ 内联钩子 + GOT 钩子 全部有效 |
| x86_64 等 | ❌ GOT 钩子仍可用，内联钩子会写到无关地址（可能崩溃） |

在非 aarch64 上编译**仅用于检查代码能否通过编译**，不能实际运行。

`make arch-check` 或 `./scripts/build.sh --check` 会给出提示。

---

## 6. 编译选项

| 变量 | 默认 | 说明 |
|---|---|---|
| `ARCH` | `$(uname -m)` | 目标架构 |
| `CROSS` | 空 | 交叉工具链前缀 |
| `OPT` | `-O2` | 优化级别 |
| `PREFIX` | `/usr/local` | 安装前缀 |

示例：

```bash
make OPT="-O0 -g3 -fsanitize=address" cli     # ASan 调试
make PREFIX="$HOME/.local" install             # 装到用户目录
make OPT="-O3 -march=armv8-a" cli             # 针对 ARMv8 优化
```

### payload 的特殊编译

payload 用独立的 `PAYLOAD_CFLAGS`：

```
-Wall -Wextra -O2 -Iinclude -fPIC -DJIYU_PAYLOAD_BUILD=1
```

- `-fPIC`：要 dlopen 进别的进程，必须位置无关
- `-DJIYU_PAYLOAD_BUILD=1`：启用 payload 内部日志
  （payload 运行在 Student 进程里，**不能**依赖控制器的
  `jiyu_debug_*` 符号，否则 `dlopen` 会因符号解析失败而失败）

## 7. 安装

```bash
sudo make install                        # /usr/local/bin
make install PREFIX="$HOME/.local"       # 用户目录
./scripts/install.sh                     # 交互式 (自动判断有无 root)
```

安装内容：

```
$PREFIX/bin/jyfree
$PREFIX/bin/jyfree-gui
$PREFIX/bin/libjyfree.so      ← 必须和 jyfree 同目录
```

> `payload_path()` 的查找顺序：
> `/proc/self/exe` 同目录 → `/usr/local/lib/` → `/usr/lib/` → `./`
> 手动放置时请保持 `jyfree` 与 `libjyfree.so` 在同一目录。

### 桌面与 systemd 集成

`scripts/install.sh` 会自动安装：

```
~/.local/share/applications/jyfree.desktop   应用菜单项
~/.config/systemd/user/jyfree.service        user 级服务
```

启用开机自启：

```bash
systemctl --user daemon-reload
systemctl --user enable jyfree.service
```

## 8. 常见编译问题

### `X11/Xlib.h: No such file or directory`

```bash
sudo apt install libx11-dev
```

只想要命令行版可以跳过 GUI：

```bash
make cli payload
```

### `'shm_open' undeclared`

缺 `librt`。glibc ≥ 2.34 已并入 libc，但旧版本需要显式链接：

```bash
# 确认 Makefile 的 LIBS 含 -lrt
LIBS := -lpthread -ldl -lrt
```

### `'FORBIDDEN' / 'brk' 指令编译错误`

payload 的补丁指令是**手写机器码**，不用编译器语法：

```c
uint32_t patch[4] = { 0x58000050, 0xd61f0200, ... };
```

### payload 编译成功但注入失败

见 `docs/04-排错手册.md`。

## 9. 编译后自检

```bash
# 1. 检查架构
file bin/jyfree bin/libjyfree.so

# 2. 确认 payload 路径能找到
./bin/jyfree --status

# 3. 确认 CLI 能跑
./bin/jyfree --help
./bin/jyfree --process      # 需要已启动极域

# 4. 看 payload 日志是否产生
./bin/jyfree                 # 注入后
cat /tmp/jyfree-payload.log
```

## 10. 源码文件清单

```
include/
  jiyu.h            控制器公共接口 (所有函数声明)
  payload_state.h   ★ 两侧共享: 特性位 / 符号地址 / 共享内存结构体
  gui.h             Xlib GUI 结构与接口

src/
  main.c            CLI 入口, 命令表, 参数解析
  gui_main.c        GUI 入口
  gui.c             Xlib 实现 (窗口/按钮/日志窗/设置框)
  inject.c          ptrace 注入引擎 + 共享内存 + 看门狗
  hook_payload.c    payload (编译为 libjyfree.so)
  process.c         /proc 扫描找 Student, systemd 集成
  utils.c           配置读写 / 日志 / 调试
```

> **v2.1 已删除**：`heartbeat.c`（`/proc/pid/net/*` 是网络命名空间级的，
> 判断不了进程级监听）、`screen.c`、`input.c`、`netfilter.c` ——
> 这些是 v1 架构遗留，功能已由特性位 + payload 钩子取代，
> 保留只会误导读者以为功能可用。

> **修改 `payload_state.h` 时务必两侧同步** —— 它同时被控制器和 payload 包含，
> 结构体布局不一致会导致内存错位。
