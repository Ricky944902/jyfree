# 01 · 逆向分析

**[简体中文](01-逆向分析.md)** · **[English](01-reverse-engineering.en.md)**

本文记录极域电子教室**统信UOS版 (aarch64)** 的实测逆向结论，以及 jyfree 的拦截原理。

所有结论来自目标机器实测 (`UOS Desktop 20 E`, 内核 `5.10.97-arm64-desktop`)。

---

## 1. 环境

| 项 | 值 |
|---|---|
| 系统 | UOS Desktop 20 E (Debian 系) |
| 架构 | **aarch64** |
| 会话 | Wayland (kwin)，但 Student 以 `QT_QPA_PLATFORM=xcb` 跑在 **XWayland** (`DISPLAY=:0`) |
| LSM | `capability,elfverify,useclinux,uosmanager`（无 SELinux/AppArmor） |
| Yama | **不存在** → 同 UID `ptrace` 天然可用 |
| Seccomp | Student `Seccomp:0`，`NoNewPrivs:0` |
| 用户 | `uid=1000`，组内**无 `input` 组**（不能直接操作 `/dev/input`） |
| 工具链 | gcc 8.3，python3.7，xdotool；**无 gdb/strace/rust** |

## 3. 进程模型

```
systemd --user
 └─ com.mythware.mcm-student.service      (RefuseManualStop=yes)
     ExecStart=StudentAgent, Restart=always, RestartSec=5s
     ├─ StudentAgent     看门狗：连 Student socket，检测 X/Wayland 异常后重启 Student
     ├─ StudentService   root，桥接 /var/tmp/com.mythware.cms.StudentService-3e8.socket
     └─ Student          --restart，实际被 StudentAgent 拉起/重启
```

要点：

- **单例机制**：`/var/tmp/com.mythware.cms.Student-3e8.socket`（`3e8` = 1000 = uid），
  QLocalServer 套接字，权限 `srwxrwxrwx`（**全局可连**）。
- **崩溃循环**：`CastAudioBase` 析构时 `QThread destroyed while running` → abort coredump
  → StudentAgent 以 `--restart` 重启。实测 14:00、14:05 各一次。
  → **这是 jyfree 必须有看门狗的原因**。
- 退出码 `1000` = 单例冲突（"application already running"）。
- 曾观察到 Student 处于 `T`（SIGSTOP）状态 → 注入前必须检查并跳过。

## 5. 网络与协议

- 教师端实测 `10.70.45.100`（mac `cc:b0:a8:4a:77:46`），学生机 `10.70.45.124`
- **cast NG（freerdp 架构）**

  - 视频/音频组播：`225.2.2.11:5547`（window 5s，maxBandwidth 204800 kbps，冗余 1.2）

## 7. 拦截点

### 7.1 内联钩子 — `CStudentMainWork`（Student 主程序）

Student 是 **ET_EXEC 非 PIE**，所以 `nm` 地址即运行地址。

| 符号（mangled） | 地址 | 作用 | 特性位 |
|---|---|---|---|
| `_ZN16CStudentMainWork14ShowLockScreenEi` | `0x441ed4` | 锁屏窗口 | `lock` |
| `_ZN16CStudentMainWork15ShowBlackScreenEi14FLAG_BACK_TYPERK7QStringjj` | `0x43fa4c` | 黑屏肃静 | `lock` |
| `_ZN16CStudentMainWork19StartMonitorPassiveEP16tagMONITORPARAMS` | `0x44e670` | 教师监视 | `monitor` |
| `_ZN16CStudentMainWork22StartRdpMonitorPassiveEP16tagMONITORPARAMS` | `0x44dbe0` | RDP 监视 | `monitor` |
| `_ZN16CStudentMainWork25ProcessDeskMonitorCommandEP19tagDESKDEMO_COMMAND` | `0x44eb44` | 桌面演示/监看 | `monitor` |
| `_ZN16CStudentMainWork16ExecuteRemoteCmdE8RSD_MODE` | `0x441a80` | 远程命令（0..3 跳转表） | `command` |
| `_ZN16CStudentMainWork20ProcessRemoteCommandEP22tagREMOTECOMMANDPARAMS` | `0x4438c8` | 远程命令处理 | `command` |
| `_ZN16CStudentMainWork30UpdatePoliciesToStudentServiceEv` | `0x44d34c` | 策略→root 服务（聚合） | `policy` |
| `_ZN16CStudentMainWork31UpdateUsbPolicyToStudentServiceEv` | `0x44cd28` | USB 策略下发 | `policy` |
| `_ZN16CStudentMainWork31UpdateWebPolicyToStudentServiceEv` | `0x44ce88` | 网页策略下发 | `policy` |

**保持可用（不挂钩）**：`DestoryLockScreen`、`RemoveLockScreenWidget`、
`DestoryBlackScreenWidget`、`StopMonitorPassive`、
`BlackScreen::unlockScreenManual`（学生主动解锁）

### 7.2 内联钩子 — `libGetAppsInfo.so.2`

纯 C 导出，被 Student 载入。符号是 **4 字节 `b` 跳转桩**，需先跳桩解析真实地址。

| 符号 | 地址 | 作用 | 特性位 |
|---|---|---|---|
| `DoAppPolicyControl` | `0x8340` | 应用策略总入口 | `apps` |
| `CloseTopWindow` | `0x8344` | 关顶层窗口 | `apps` |
| `KillProcess` | `0x82f8` | 杀学生进程（调 `kill`/`system`） | `apps` |
| `CloseApps` | `0x85f0` | 关闭应用 | `apps` |
| `CloseWndByWindowId` | `0x856c` | 按 window id 关窗 | `apps` |
| `GetApplicationList` | `0x82f0` | 进程枚举 | **不挂钩** |
| `StartGetIcons` | `0x8348` | 图标枚举 | **不挂钩** |

> `GetApplicationList` 不挂钩：返回 ABI 风险（结构体大小/版本不匹配会崩）。

该库还导入 `XTestFake*` + `XSendEvent`。`XSendEvent` **不能全局封**，
只封输入类事件 `type ∈ {2,3,4,5,6}`，因为它也被用于发 `WM_DELETE_WINDOW` 关广播窗口。

### 7.3 内联钩子 — `libcastng.so.0.1`（freerdp 输入回调）

**教师反向控制的最终落点**。

| 符号 | 地址 |
|---|---|
| `_Z22tf_peer_keyboard_eventP9rdp_inputtt` | `0x22ebf0` |
| `_Z30tf_peer_unicode_keyboard_eventP9rdp_inputtt` | `0x22e940` |
| `_Z19tf_peer_mouse_eventP9rdp_inputttt` | `0x22e750` |
| `_Z28tf_peer_extended_mouse_eventP9rdp_inputttt` | `0x22e560` |
| `_ZN10CastClient12setInputGrabEb`（thunk） | `0x2083c0` |

castng **无任何 X11/xcb 直接导入** → 截屏委托给 libDesk。

### 7.4 GOT 钩子 — X11 层（所有已加载 ELF 通用）

`dl_iterate_phdr` 遍历 → 解析 `PT_DYNAMIC`（`DT_JMPREL`/`DT_RELA`）→
按名字匹配 `R_AARCH64_{JUMP_SLOT,GLOB_DAT}` → `mprotect` 后改写。

| 目标 | 处理 |
|---|---|
| `XGetImage` / `XShmGetImage` | 取真实帧后覆写像素（freeze / black） |
| `XGrabKeyboard` / `XGrabPointer` | 返回 `0`（Success）但不真的抓取 |
| `XTestFakeKeyEvent` / `XTestFakeButtonEvent` / `XTestFakeMotionEvent` | 吞掉 |
| `XWarpPointer` | 阻止指针锁定 |
| `XkbLockModifiers` | 拒绝 |
| `XSendEvent` | 仅拦 `type ∈ {2..6}` |

> `libcast-x11.so`（126MB）导入 `XGrabKeyboard`/`XUngrabKeyboard`/`XUngrabPointer`/
> `XTestFake*`/`XkbLockModifiers`/`XGetImage`/`XWarpPointer`/`XSendEvent`/`XShm*`。
> RELA 已实测（例：`XGrabKeyboard` GOT 槽 `r_offset=0x131d188`）。
> 因是**按需 dlopen**，payload 每秒重扫新模块。

**为什么有效**：Qt 自身走 xcb 不经 Xlib → 封 Xlib 不影响 Qt 窗口系统；
而极域的 `libcast-x11` 走 Xlib → 封 Xlib 有效。

### 7.5 截屏 — `libDesk.so.2`

| 符号 | 地址 | 说明 |
|---|---|---|
| `XGetImage`（GOT） | — | **唯一实际截屏入口**（当前所见） |
| `CDesktopCapture::StartSendThread` | `0x132f0` | 采集线程启动 |
| `QtScreenCapture::grabScreen(QString)` | `0x16264` | 指定窗口截取（返回 QImage，**sret ABI，不挂钩**） |
| `CDesktopCapture::RequestFullScreen` | PLT | 监视全屏请求 |

## 8. 权限模型

- `Student`/`StudentAgent` = **普通用户进程** → 同 UID `ptrace`/`dlopen`/`mprotect` 全部可行
- 键鼠控制 / 锁屏 / 监视 / 杀进程 **全部在用户态 Student 进程内**
- root 侧仅剩：网页策略（`cms_nf.ko`）、USB Minifilter、setuid `Launcher`
- **开机已加载的策略无法从用户态更改** → 只能阻断后续策略下发（已知限制）
- systemd user 单元 `RefuseManualStop=yes` → 只能直接发信号，不能 `systemctl stop`

## 9. jyfree 的注入方案

```
jyfree (控制器, aarch64 用户态)
 ├─ inject_attach      PTRACE_ATTACH → 保存 regs
 ├─ inject_call        在目标栈写 brk #0，PC=func，LR=陷阱地址 → 远程调用
 ├─ inject_dlopen      远程 mmap 写路径 → 远程调 dlopen(RTLD_NOW)
 ├─ inject_detach      还原 regs → DETACH
 ├─ 看门狗             1s 轮询：pid 变化 / start_time 变化 / payload 心跳停滞 → 重注入
 └─ 共享内存           /dev/shm/jyfree.state（特性位 + 计数器 + 心跳）

libjyfree.so (payload, dlopen 进 Student)
 ├─ constructor        挂共享内存 → 装内联钩子 → 扫 GOT → 起协调线程
 ├─ 内联钩子           ldr x16,#8 ; br x16 ; .quad detour   (16 字节, 无 trampoline)
 ├─ GOT 钩子           dl_iterate_phdr 全 ELF 扫描
 ├─ 协调线程           每秒更新心跳 + 检测 libcast-x11 新加载
 └─ destructor         还原所有内联钩子（uninject 时）
```

**返回约定**：`w0 = 0`，与厂商空桩一致。
若某调用点检查 bool "已处理"，需改为返回 `1`。

## 10. 待验证 / 已知不确定

1. **Wayland 下 X11 钩子的实际效果** — 会话为 XWayland，`XGrabKeyboard`/`XTestFake*`
   可能天然只影响 X 客户端。需课堂实测 `counters` 增量。
2. **谁在 SIGSTOP Student** — 未定论（厂商重启时序 or 人为）。看门狗按状态分流处理。
3. **监视/广播的图像路径是否确经 `libDesk` 的 `XGetImage`** —
   需真实课堂验证 `counters` 的「截屏」计数。
   注意：教师广播是 **RDP 流**，走 `libcast-x11.so`，与 `libDesk` 是**不同路径**。
4. **内联钩子返回约定** — 见 §9。
5. **UDP 未认证命令通道**（`4788/5512/5662/...`，对应 Windows 版 `Jiyu_udp_attack`）
   尚未逆向 → 潜在升级项。
6. **QLocalServer 本地协议**（socket 全局可连 `srwxrwxrwx`）Qt 帧格式未逆向
   → 潜在命令注入面。
7. **setuid `Launcher`** — 可疑提权面，**明确不在本项目范围**。
8. 学生主动举手/解锁、关闭屏幕广播窗口（xdotool 按 `_NET_WM_PID`）— 可选，未实现。

## 11. 换版本必须重新确认符号地址

```bash
nm /opt/mythware/classroom-management/Student | grep -E 'ShowLockScreen|StartMonitorPassive'
readelf -s libGetAppsInfo.so.2 | grep -E 'KillProcess|CloseTopWindow'
```

然后更新 `include/payload_state.h` 里的 `SYM_*` 常量。
